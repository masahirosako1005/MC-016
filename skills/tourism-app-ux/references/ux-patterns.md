# 画面の型（理由と実例）

実例はすべて観光アプリ「ひとめぐり」（旅先で会ったお店の人にまた会いに行きたくなるアプリ）のもの。
題材が変わっても使えるよう、各項目は「型 → 理由 → 実例」の順に書いてある。

## 1. 全体の構成

### 場面を先に並べる
利用者の時間の流れを 3〜5 場面に分け、各場面に「開く理由」と主な画面を 1 つずつ割り当てる。

| 場面 | 開く理由 | 主な画面 |
|---|---|---|
| 行く前 | どこへ行くか決めたい | 計画 |
| その場 | 次にどこへ、何ができるか | マップ → 場所の画面 |
| その夜 | きょうをふり返りたい | 思い出 |
| しばらく後 | 便りが届いた | 思い出（便り）→ 計画 |
| 次の機会 | 持っているものを使いたい | クーポン |

理由: 「その場」だけのアプリは、帰ったら開かれない。帰ったあとに届くもの（便り、次にしか使えないクーポン）を最初から設計に入れる。

### 入口は、利用者がもともと探しているもの
観光なら入口は「場所」。アプリが足したい価値が「人」でも、最初の画面は場所のカードにし、人は「ここにいる人」として中に添える。旅前の段階では人に操作ボタンを付けない。

理由: 人を入口にした最初の版は「人を選んだつもりがないのに、会いに行く流れに乗せられる」違和感があった。知らない概念を入口にすると、最初の一歩が踏み出せない。

### 下タブ
- 5 つまで。1 タブ = 1 目的。名前は利用者が口にする言葉（計画／マップ／思い出便／ひとめぐり帖／クーポン）。
- 「タブを増やしたくないから 1 つのタブの中で切り替える」は失敗した。目的が別なら別のタブにする。
- 並びは時間の順（行く前 → その場 → あと）。
- 未読・未処理は強調色の小さな点で示す（数字は必要なときだけ）。

### ヘッダ
上に固定。左に戻る、中央に画面名、右に「？」（使い方）と設定。戻る先は「ひとつ前」ではなく、**その作業の起点**（撮影のあとは場所の画面へ）。

## 2. いまやること

各タブの一番上に置くカード。構成は「小さなラベル・文 1 つ・主ボタン 1 つ・（あれば）キャラクター」。

- サーバー側で利用者の状態から 1 つだけ決めて返す（例: 計画なし → 「行きたい場所を選びましょう」、旅の当日 → 「次は○○へ」、その夜 → 「きょうの思い出が届いています」）。
- ここに出した内容を、同じ画面の別の場所（下の固定バーなど）でもう一度出さない。
- 何もすることがないときも消さない。ボタンなしで一言（「次の旅まで、あと 3 週間」）。
- 濃いテーマ色の面に紙色の文字。主ボタンは紙色の面。ラベルとボタンの中の印、左の帯に強調色（濃い面の上は強調色がいちばん映える）。

理由: 機能が増えるほど、利用者は「いま自分は何をすればいいのか」が分からなくなる。画面ごとに答えを 1 つ先頭に出しておくと、説明文が要らなくなる。

## 3. 一覧とカード

- **カードは写真 + 名前 + 一言 + 添え情報**。写真には下向きに濃くなる薄い膜をかけ、その上に名前を載せる。
- **選ぶ操作はカードをめくる形にできる**（右 = 行く／左 = 行かない）。ただし下に同じ働きのボタン 2 つを必ず置く。
- **めくるカードは「積み重ね」に見せる**。下のカードを少し小さく・少し下にずらして見せ、上をめくるとそのまま上がってくる。実装では、リストの key を項目の ID にする（位置の番号にすると、同じ要素が使い回されて「戻ってくる」動きになる）。
- **おすすめの理由をタグで添える**。左上に 1〜2 個。例: 「前回行けなかった場所」「春に行った（4/12）→ 秋はどう？」「♡ 旅のあとに『行きたい』」。該当する条件がなくなれば自動で消える。
- **並べ替えの根拠は利用者自身の行動**（行きたいと言った → 先頭）。人気順・評価順にはしない。
- **選んだ時点で「回りきれるか」を見せる**。選ぶたびに、数と所要時間の目安（「外湯 3・お店 2／およそ 2 時間 20 分」）を出す。出す場所は「いまやること」か画面下の固定バーの**どちらか 1 か所**（両方に出すと同じ情報が二重になり、固定バーが一覧も隠す）。行く前の不安は「一日で回れるか」がいちばん大きい。回る順は近い順に自動でつなぎ、並べ替えの操作は付けない（小さな街では手で直す手間のほうが大きい）。
- **場所は名前を読まなくても見分けられるように**。場所ごとに一文字（鶴・月・柳）や紋、色のちがう絵を割り当て、一覧・地図のピン・記録・集める枠で同じものを使う。
- 手順が複数あるときは、上に細い手順帯（1. 選ぶ → 2. 整える → 3. 日を決める）。いまの段をテーマ色、済みを中間色。

## 4. 地図

- 外部の地図サービスを使えない・使わない場合は、文字のない地形の絵を背景にして、地名・ピン・現在地を SVG で重ねる。文字は絵に焼き込まない（位置や名前を後から直せる、文字の大きさ設定に追従できる）。
- **ピンをタップ → 地図の上にポップアップ**。場所名・状態（営業中など）・住所・電話・いる人・主な操作ボタンを入れ、画面を移らずに済ませる。「くわしく」で詳細へ。
- **ポップアップで、選んだピンやほかのピンを隠さない**。地図の外（すぐ下）に出すか、選んだピンが下半分にあるときは上側に出す。出したあと、選んだピンが見えていることを確かめる。
- **ピンを直接押して状態を切り替えない**。何が起きたか分からないので、切替はポップアップの中のボタンで。
- 地形には色をつける（川・緑地・道）。「これから行く」ピンは強調色、済みはテーマ色にチェック。ピンには回る順の番号か、場所を見分ける一文字を入れる。
- 凡例を増やさない。印は 3 種類まで（例: 番号つき = きょう行く、チェック = 済み、青い点 = 現在地）。
- 現在地を点滅させない。

## 5. 撮影・読み取り

- **専用の 1 画面にする**。元の画面の中に埋め込まない。流れは「カメラ → 撮る → 確認 → 元の画面にもどる」。
- **シャッターは映像のすぐ下に、大きく 1 つ**。フレームなどの選択肢はその下に横スクロールで並べる。スクロールしないと撮れない配置にしない。
- 撮影が複数種類あっても、配置と流れを同じにする。
- 内カメラで文字を撮る用途には左右反転の切替を付ける。
- **記録するだけの画面も同じ考え方**。絵（または写真）のすぐ下に主ボタン 1 つ。写真やひとことなどの任意の入力は主ボタンの下に置くか、記録したあとに足せるようにする。
- 読み取り（レシートなど）は「撮る → 読み取り中の演出 → 値を確認して登録」。読み取った値は入れておくが、**確定は必ず利用者**。
- 撮ったものは、もどった先の「撮る」ボタンのすぐ下に並ぶ。

---

## 6. 記録とふり返り

- **実物の比喩を 1 つ使う**。思い出はコルクボードに、写真はポラロイド風、一言は付箋。データの一覧表より「あとで見返したくなる」。
- **入力欄と表示を分ける**。付箋に直接書かせる案は、どこを押せば書けるのか分かりにくく戻した。上に入力欄、貼ると下のボードに付箋で出る。
- **ふり返りの画面は見るだけ**。そこから開いた詳細にも操作ボタンを置かない。
- **集める画面は「人（もの）のカード」を主役に**。会えた人は色つき、まだの人はシルエットと「？？？」。上に「N / 8」と進み具合の棒。
- **空き枠ごと見せる**。集める枠は全部並べ、まだの枠は点線と薄い印で残す。下に「外湯はあと 5 つ。つづきは、また次の旅で」のように一言。残りが目に見えることが、また来たい気持ちにいちばん効く。責める言い方にはしない。
- **計画どおりでなくても記録できる**。行きたいに入れていない場所も、寄ればそのまま記録できる。
- 記録の表は、新しい 3〜5 件と合計だけ。残りは「すべて見る」。

## 7. 進み具合の見せ方（ゲーム要素）

- **利用者に見せる物差しは 1 つ**。「会えた回数」だけにして、帯の色 3 段階（はじめまして → また会えたね → おなじみ）で示した。
- 最初は「種 → つぼみ → 花」「季節のスタンプ」「回数の帯」を同時に見せていて、どれを見ればいいか分からないと指摘された。2 つ目・3 つ目は画面から外した。
- **外すときはデータと API を消さない**。画面から呼ばなくするだけ。あとで戻す・運営側で使う余地が残る。
- 段階の名前は利用者にかける言葉にする（レベル 1・2・3 ではなく）。
- 罰を作らない（逃しても枯れない、失効で責めない）。

## 8. 抽選・ポイント・クーポン

- **結果はサーバーが先に確定し、演出はあとから結果に合わせる**。演出の見た目から確率を読み取れないようにする（ルーレットのマスは同じ広さで、当たり・はずれを交互に）。確率の表は「当たる確率を見る」に折りたたんで必ず見られるようにする。
- **結果はスクロール不要のポップアップで**。そこに「誰が渡してくれたか」を出すと、ただの当選が体験につながる（会ったことのある店の人が渡す）。
- 回る・動くものは、はみ出しが周りを揺らさないよう丸い箱（`overflow: hidden`）に閉じ込める。
- クーポンは「使える場所」で使う。使う操作は「ボタン → 確認 → 使用済み」。
- お金に関わる数字（還元率、補填額）は利用者の画面に出さず、運営の画面だけ。

## 9. 初回ガイドとチュートリアル

- **初回に 3 枚**。1 枚 = 見出し 1 つ + 図 1 つ + 2 行。番号は強調色。最後のボタンは最初の画面へ連れて行く（「計画をはじめる」）。
- **画面ごとの図解を初回に 1 度だけ**。ヘッダの「？」でいつでも再表示。設定にも「使い方をもう一度見る」。
- 図は実画面の縮小ではなく、要点だけの簡単な絵（SVG）。
- 見たかどうかは端末に保存。保存できなくても動くよう try/catch で囲む。

---

## 10. 文言

- ボタンは動詞で、利用者の言葉（「会えた」「行きたい」「撮る」「この予定で決める」）。
- 見出しは短い名詞。説明文は基本的に書かない。書きたくなったら「いまやること」か初回ガイドに回す。
- 人の名前は自然な呼び方（苗字 + さん）。利用者は ID ではなく呼び名。
- 日付は「10/24 の思い出」のように、画面で意味が通る形に。「便」「件」などの内部の呼び名を出さない。
- 設定で「やさしい日本語」に切り替えられるよう、文言は辞書 1 か所にまとめる（余裕がなければ最初に削る項目）。
- 失敗の文は、何が起きたかと次にできることを 1 文で。謝罪を重ねない。

## 11. 運営の画面

- **スマホでも PC でも使える**。720px 未満は 1 列、表は横スクロール。
- **開くたびにホームから**。ホームの先頭は「次の一手」: データから規則で組み立てた提案（例: 「はじめましての人が 12 人。お礼の便りを送りませんか」）と、下書きや編集欄へ飛ぶボタン。数字の一覧はその下。
- **立場ごとに機能を分ける**（地域全体 = 指標・イベント・設定、個々の店 = 来訪のようす・お店の情報・便り）。立場は本番では権限で決まるので、画面上部の切替は置かない。デモでだけ必要なら、隅の小さな設定ボタンに入れる。
- **機能の切替は下線つきのタブ**（選択中は太字 + 強調色の下線）と、「運営の窓 › 立場 › 機能」のいまの場所表示。丸いチップの列は「選択肢なのか絞り込みなのか」分かりにくく、やめた。
- **説明文を消す**。見出しの下の説明、指標の注記、タブの説明は、最初に全部書いてから全部消すことになった。
- **グラフはテーマ色 1 系列 + 強調色で 1 点だけ強調**。自前の SVG で十分。
- **格付けを作らないための線引き**:
  - 点数の平均や分布は全体でだけ出す。個々の店には点数を見せず、寄せられた声（タグの件数と文章）だけ。
  - タグは定義した順に並べる。多い順に並べ替えない。
  - 比べる相手は平均（地区平均・全体平均）。順位は出さない。
  - 3 件未満は集計を出さない（個人が分かってしまうため）。
- 運営が編集した内容（店の紹介・営業時間）は、利用者の画面にすぐ反映される。再起動で初期値に戻さない。
- 絞り込みで宛先を選ぶ操作は、条件に合う人数をその場で表示する。

## 12. 使えないときの逃げ道

- カメラが使えない → 写真を選ぶ → 用意した絵。どの段でも最後まで進める。
- 位置情報がない → 計画の次の場所を現在地の代わりに使う。
- 共有機能がない → ダウンロード。
- データが空 → キャラクターと一言、次にできることのボタン。
- 読み込み中 → キャラクターと「読み込み中」。骨組みの点滅は使わない。
- 通信エラー → 控えめなお知らせ 1 つ。画面は消さない。
