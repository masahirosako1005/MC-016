# 見た目の型

土台は `assets/tokens.css`（変数）と `assets/base.css`（部品）。ここでは「値をどう決めるか」と「どう使い分けるか」を書く。

## 1. 世界観から決める

題材から連想できる素材を 1 つ選び、そこから書体・小さな飾り・絵の描き方を導く。
見本（ひとめぐり）は「島と港町」から「藍染と和紙の手紙」を選び、テーマ色 = 藍 `#1b2a44`、背景 = 紙 `#fbfcfd`、強調色 = 山吹 `#e3a21a` とした。

これは 1 つの例で、ほかの題材の答えはここに書いていない。題材ごとに、下の手順で自分で決める。

## 2. 色の決め方

コードを書く前に決め、設計メモの先頭に 4 色を色名と値で書く。

### 手順

1. **題材の実物から、色の候補を拾う**。その土地・その題材に実際にあるものを 5 つほど挙げ、それぞれの色を書き出す（のれん、屋根瓦、名産、土地の花、祭りの衣装、海や山の色、看板など）。ここを飛ばして「温泉だから○色」と決めない。
2. **テーマ色と強調色を、候補の中から選ぶ**。
   - テーマ色: ひと目で色名で呼べる色。黒・こげ茶・濃い灰色のように黒に見える色は選ばない（画面全体が無彩色に見え、のっぺりする）。文字にも使うので、背景の上でコントラスト比 7:1 以上が目安
   - 強調色: テーマ色と並べて、はっきり映える色。テーマ色が寒色なら暖色、暖色なら寒色か明るい黄。テーマ色より明るく鮮やかに。暗い色どうし・似た色相どうしは選ばない
   - 選んだ理由を、題材の実物と結びつけて 1 行で書けること（「駅舎の屋根の色と、名産のみかんの色」のように、実物の名前で）
   - この文書や見本に出てくる組み合わせをそのまま使わない。同じ題材でも、土地が違えば色は違う
3. **背景の色を決める**。テーマ色をごくわずかに混ぜた、紙のような明るい色。真っ白はカードに使い、地との差で段差を出す。
4. **字の色を決める**。テーマ色そのもの、またはさらに濃くした色。補足の小さな字はテーマ色の中間の濃さ（背景の上で 4.5:1 以上）。
5. **並べて確かめる**。テーマ色の面の上に強調色の丸を置いた見本を思い浮かべ、互いを引き立てているか見る。弱ければ 1 か 2 に戻る。

### 4 色から変数を作る

- テーマ色の濃淡を 6 段階作る（900 = テーマ色そのもの、700、500、300、100、050）。色相は変えず、明るさと鮮やかさだけ変える。
  - 900: 見出し・本文・主ボタンの面・選択中
  - 700: リンク・補助ボタンの文字
  - 500: 補足の文字
  - 300: 強めの枠線・無効
  - 100: 枠線・区切り
  - 050: 薄い面（済み・選択の背景）
- 強調色は、そのものと、薄い面用、薄い面に載せる文字用の 3 つ。
- 部品（ボタン・枠・文字・札）に使うのはここまで。成功の緑・警告の赤も作らず、テーマ色の濃淡と強調色で表す。例外は、意味そのものが色である場合だけ（銅・銀・金の帯、コルクボードの茶）。

### 強調色の使い方

強調色は「見てほしいところ」の色。**どの画面でも、開いた瞬間に目に入る大きさで使う。**

- 使う場所: 進み具合の棒、地図の「これから行く」ピン、達成の印・帯・スタンプ、選択中タブの下線、数の札、未読の印、ガイドの番号、主ボタンの中の印、大事な数字 1 つ
- 量: 1 画面に 1〜3 箇所、合わせて画面の 1 割ほど。小さな点 1 つだけでは足りない（強調色がないのと同じに見える）
- 避ける: 本文の文字色にする、広い面を塗る、4 箇所以上に散らす
- 強調色の上に文字を載せるときは、白ではなく濃い色に。小さな札なら太字の白でも可
- テーマ色の濃い面（「いまやること」カードなど）の上は、強調色がいちばん映える場所。ここに必ず 1 つ置く

### 絵は色の決まりの外

場所の絵・地図・キャラクター・写真には、上の決まりを当てはめない。

- 場所ごとに色を変え、朝・夕・夜、川・山・木など、その場所の特徴が分かる小さな風景にする
- 絵の中にもテーマ色と強調色を入れる（夜空にテーマ色、月や灯りに強調色）。画面となじむ
- 地図は地形に色をつける（川は水色、緑地は緑）。ピンや文字はテーマ色と強調色で
- 絵まで単色・記号だけにすると、整ってはいるが地味で、題材らしさが消える

### 高コントラスト設定
設定で切り替えられるようにする。変数を上書きするだけで済むよう、部品は必ず変数を参照する（色の値を直接書かない）。見本は `tokens.css` の `[data-theme="contrast"]`。

## 3. 書体と文字

- 見出し・日付・題名: 明朝（Yu Mincho → Hiragino Mincho → Noto Serif JP）、太さ 600、字間 0.02em
- 本文・ボタン: ゴシック（Yu Gothic UI → Meiryo UI → Hiragino Sans → Noto Sans JP）
- 外部フォントは読み込まない。OS に入っている書体だけで組む（表示が速く、通信なしで動く）
- 基準 16px、行間 1.6。設定で 14 / 16 / 19px に切替。寸法は rem で書く
- 画面の題名 1.5rem、節の見出し 1.15rem（左にテーマ色の 3px 線）、補足 0.92rem、最小 0.72rem（下タブ）
- 数字の列は等幅数字（`font-variant-numeric: tabular-nums`）で右寄せ

## 4. 寸法

- 角丸: 部品 8px、ポップアップや大きなカード 12〜14px、チップ・札は完全な丸
- 押せるもの: 高さ 48px 以上（チップは 36px 以上、まわりに余白）
- 画面の左右余白 16px、内容の最大幅 560px（運営の画面は制限なし）
- カードの内側 14px、部品どうしの間 10px
- 下タブの高さ 64px。固定の部品（お知らせ、下の固定バー）はこの高さを変数で参照して上に載せる

## 5. 面・線・影

- カード: 白地 + テーマ色 100 の 1px 枠。影なし
- 強調したいカード: 枠をテーマ色 900 に（面は変えない）
- 手紙ふうのカード: テーマ色 300 の枠 + 上から下へ白 → 紙のごく薄いグラデーション
- 影を使うのは、浮いているものだけ（ポップアップ、お知らせ、めくるカード）。色は黒ではなくテーマ色を薄く
- 地にごく薄い質感を入れてよい（テーマ色 2〜3% の細かい点の繰り返し。画像は使わない）

## 6. 部品の使い分け

| 部品 | 使う場面 | 見た目 |
|---|---|---|
| 主ボタン | 画面で 1 つ | テーマ色の面 + 紙色の文字 |
| ふつうのボタン | 2 番目以降 | 白地 + テーマ色の枠と文字 |
| 控えめなボタン | とじる・やめる | 薄い枠 + テーマ色 700 の文字 |
| 済みのボタン | 押したあと | テーマ色 050 の面、枠なし |
| チップ | 複数から選ぶ・絞り込む | 丸い枠。選択中はテーマ色の面 |
| 札（バッジ） | 状態を示すだけ（押せない） | 小さな丸い札。濃淡 3 種 |
| 2 択の切替 | 同じ画面の 2 つの見方 | 枠でつないだ 2 つのボタン |
| 下線タブ | 機能の切替（運営の画面） | 文字 + 下線。選択中は太字 + 強調色の下線 |
| 折りたたみ | 必要な人だけ見る情報 | 見出し + 「＋／－」 |
| お知らせ | 操作の結果を一言 | 半透明の紙 + テーマ色 700 の文字。3 秒で消える |
| ポップアップ | 結果・確認 | 中央、紙色、最大幅 360px。スクロールなし |

チップと下線タブを混ぜない。チップは「選ぶ・絞る」、タブは「場所を移る」。

## 7. 動き

- 入るとき 0.2〜0.25 秒、ease。お知らせとポップアップは下から 8px 上がりながら現れる
- 達成の演出は 1 回だけ、1.2 秒以内
- 常に動き続けるものは置かない（読み取り中の走査線など、処理中を示すものだけ例外）
- 「視差効果を減らす」設定（`prefers-reduced-motion`）のときは動きを止める
- 回転・拡大するものは親を `overflow: hidden` にして、まわりの配置を揺らさない

## 8. 絵と素材

- アイコンは線の太さと角の丸みをそろえた SVG。24px。選択していないときは不透明度を下げる
- 場所の絵は、場所ごとに描き分けた小さな風景（色つき）。記号 1 つで済ませない。一覧・記録・ふり返りで同じ絵を使う
- 場所には一文字・紋などの「見分ける印」も割り当て、地図のピンや集める枠で使う
- 写真は 3:2 を基本に、角丸、下に向かって濃くなる膜（テーマ色 5% → 45%）をかけて上に文字を載せる
- 人の絵は丸く切り抜き、顔が切れないよう上寄せ。会えた人は強調色の細い輪、まだの人は薄く・灰色がかりに
- 地図の上の文字や印は絵に焼き込まず、SVG で重ねる
- 借りた素材は出典・ライセンス・取得日を 1 つの文書（例: `docs/licenses.md`）にまとめる。素材は自分のサーバーから配信する（外部の配信元を直接参照しない）

## 9. キャラクター

置くなら、飾りではなく役割を持たせる。

- 置き場所: いまやること、初回ガイド、読み込み中、空の状態、お知らせ、お礼
- ポーズで意味を分ける（手をふる = 案内、考え中 = 読み込み、ごめんね = 失敗、ありがとう = 完了）
- 場所や季節で小物・衣装を変えると、集めたくなる要素になる
- キャラクター自身の配色もテーマ色 + 強調色 1 点に合わせる
- 既存の作品のキャラクターを使わない。題材から自作する

## 10. 印刷・書き出し

- 印刷用のレイアウトは別に用意（ハガキ判 100×148mm など）。下タブ・ヘッダ・ボタンは `@media print` で消す
- 画像として保存するものは、画面の合成と同じ寸法の canvas に描く。SVG の中に置いた外部画像は canvas に描けないので、写真や人の絵は canvas に直接描き、飾りと文字だけ SVG にする
