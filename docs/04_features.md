# 04 機能

## 旅前（計画）
- 計画: 7 つの場所カード（風景写真）がメイン。各カードに「ここにいる人」（1〜2 人、付加情報、ボタンなし）。地区・季節チップ、検索、自前 SVG 諸島マップ（点は場所）。
- 旅人の声: SNS 風の架空投稿（固定 seed）。件数・いいね・順位は出さない。本番では SNS 公式 API 等に差し替える前提。
- つぎの旅（計画）: 利用者につき有効な計画 1 つ。場所を「行きたい」で追加、日を決める。その日に会えそうな人（定休日で判定）・花になる種・使えるクーポンを表示。おもいで便の「行きたい」は その人のいる場所を自動で候補に入れる。マップでは計画の場所が先頭。

## 旅中（マップ）
- 予報: 店の定休日（曜日）と営業時間だけで判定。約束の期間が今日を含めば「いま〇〇の時期」を添えて上位に。
- 会えた: 自己申告。`UNIQUE(user_id, person_id, met_on)` で同じ日に同じ人は 1 回。関係 = 会えた別日数（1 / 2 / 3+、帯は銅・銀・金）。
- 場所への到着は申告させない（会えた・レシート・写真が到着の記録）。スタンプラリー要素は外した。
- 種: 初めて会えた日に、次の季節の約束が種になる。約束の季節に、その人に会えた日だけ 1.2 秒長押しで果たす → さらに次の季節の種。逃しても枯れない（つぼみのまま翌年へ）。人ごとに未達の種は 1 つ（部分 UNIQUE インデックス）。
- AR フォト: `getUserMedia` のカメラ映像に SVG を重ねて canvas で合成 → PNG。マーカー認識・空間追跡はしない。今日「会えた」人とだけ撮れる。その場所のほしまる PNG かフレーム PNG（`img/frames/`、場所ごとの★フレームはその場所でだけ選べる）を canvas に直接描き、日付の札は SVG。カメラ不可→写真を選ぶ→その場所の風景写真の順に自動で切り替え。レシート撮影は内カメラだと鏡文字になるため**左右反転**（facingMode が environment でなければ既定で反転、ボタンで切替。保存画像も同じ向き）。サンプル写真 4 枚を seed（前回の旅の風景 10/14〜16）。ダウンロード／Web Share／ハガキ判印刷。
- レシート: 写真必須（PNG/JPEG/WebP、5MB、先頭バイト判定）、SHA-256 重複は 409、金額 1〜100,000、pt = floor(金額 × 率)、率はスナップショット、今日の日付のみ。画像は 7 日で削除（起動時）、数値は残す。

## ポイント・抽選・クーポン
- 100 pt で 1 回。結果は API が先に決め（減算・在庫・付与は 1 トランザクション）、画面は**ルーレット演出**（確率の大きさで区分を分けた円盤。矢印が止まった区分が結果）の後に**ポップアップ**で見せる。`POST /api/draws` は `presenter`（会ったことのある、その区分の店の人。会えた日数が多い順）を返し、その人が渡す演出にする。いなければ ほしまる。商品はカテゴリ単位（飲食／宿泊／体験／物販）のクーポン + はずれ。重み・在庫・額面は運営の窓で変更。在庫 0 の重みは はずれ に合算し、確率表示も同じ計算。
- ポイント減算・在庫減・クーポン付与・抽選記録は 1 トランザクション（`BEGIN IMMEDIATE`）。
- クーポン: 当選翌日〜当選日 + 1 年。同カテゴリの店ページで 1.2 秒長押し → 使用済み（店・日時・額面を記録）。
- 補填: 使われたクーポンの額面合計を店ごと・月ごとに集計（運営の窓だけ）。

## 旅後
- おもいで便: 活動日の 18:00 以降に開封可。中身は毎回記録から組み立て（会えた人・スポット・写真・買いもの）。保存は一言日記 140 字と「行きたい」だけ。提案 3 つ = 別の季節に、また／別のイベント／まだ行っていない場所（そこにいる人）。旅の最終日 + 30 日以降は同じ便が再表示され、「行きたい」を先頭に、次の季節まで あと N 週間。
- ひとめぐり帖: 人と関係、種と花、アルバム、これまでの旅（活動日の間隔 2 日以内で 1 つの旅）。

## 指標 `GET /api/metrics`
再訪率／訪問間隔の中央値／旅の後の起動率／満足なのに再訪なしの割合／地区ごとの消費額／クーポンを使った再訪／つぎの旅→来訪率。各値に n と dummy_n。3 人未満の区分は null。

## 運営の窓 `#/admin`
- 次の一手（`GET /api/admin/advice`、`GET /api/admin/shops/{id}/advice`）: デモではデータから規則で組み立てる（花の人・次の季節の種・はじめましての人・地区平均との比較・イベント・来訪計画／DMO は季節の便りの準備・満足なのに再訪なし・地区の偏り・イベント未登録・前月比・来訪計画）。本番では生成 AI が下書きし、人が確認して送る想定。順位・格付けは作らない。
- 便りの宛先: `GET /api/admin/shops/{id}/audience?stages=first,again,regular&seeds=none,bud,flower` で内訳と絞り込み後の人数。`POST .../messages` の `stages`／`seeds` で同じ条件を適用（両方指定したときは両方を満たす人）。
- 店の情報: `PUT /api/admin/shops/{id}` に address・phone・url・nearest・notes・open_time・close_time・closed_weekday。場所の詳細 `GET /api/places/{id}` の `info` に店ごとにまとめて返す。
指標、CSV 取り込み（確認→取り込み／アップロード、件数と失敗行の理由）、還元率、商品、補填、直近レシート、変更履歴。DEMO_MODE に関係なく動く。

## デモ層（DEMO_MODE=1 のみ）
模擬の時計（DB 保存）。`/api/demo/{state,trip-day,night,after30,next-season,clock,fix-lottery,reset}`。`#/present` は同一オリジン iframe で本体を動かし、帯のボタンで時計を進めて `postMessage` で画面を切り替える。DEMO_MODE=0 では `/api/demo/*` は JSON 404。
